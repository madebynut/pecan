# Pecan 验收说明

建议先打开 `acceptance.md`，再检查 `long-code.md` 和 `network-image.md`。这些文件与图片放在同一目录，保持目录结构即可。`welcome.md` 是欢迎文档，`callouts.md`、`code-layout.md`、`reading-style.md` 和 `mermaid-viewer.md` 是此前使用的分项样例。

多语言自动格式化专项见 `auto-formatting.md`，包含嵌套块、无效输入和未知语言的保留测试。

## 阅读区验收

配置格式化专项使用 `configuration-formatting.md`，检查加载时自动格式化、缩进切换、复制与源文不变；代码右键只显示正文菜单。Word 语言栏最小 24pt，PDF 语言栏 26pt。

语言图标专项使用 `language-logos.md`，检查亮暗主题、别名、提示块内代码、未知语言与三种导出；跨页仍使用 `code-export-appearance.md`。

## Word 与 PDF 验收

从顶部「文件」菜单或正文右键菜单分别导出 `acceptance.md`。代码配色专项请打开 `code-export-appearance.md`，依次导出 PDF、Word、HTML，检查普通代码、无语言代码、提示块内代码和 90 行长代码：语言标识右对齐，语言栏 #F4F4F4、代码正文 #FCFCFC，续页完整且保留边框。打开 Word 时先使用 100% 缩放，避免页面适配缩放掩盖细小留白。

- [ ] Word 第 1、2、6 节：行内代码为可编辑文字，灰底覆盖左右留白、没有边框，同一行内灰底上下齐平，没有额外放大上下间距；短代码、中文、标题与表格中的代码不贴边。
- [ ] Word 正文：行距适中，较高的公式仍完整；引用、提示块有四周内边距，多行内容没有挤在边缘。
- [ ] Word 表格：短内容与多行内容在同一行中垂直居中，内容没有丢失或被截断。
- [ ] PDF 第 4 节：说明、建议、重要、注意、谨慎分别显示蓝、绿、紫、橙、红色背景；标题与内容保持相邻。
- [ ] 两种导出：标题、代码、数学、图表与本地图片完整；分页后容器边框正常，没有文字重叠。
- [ ] 导出 `long-code.md`：跨页代码内容完整，继续页有边框，最后一行没有丢失。

Word 是原生可编辑文档，PDF 是固定页面。页面宽度、字号和表格换行遵循纸面排版，不能把阅读区的水平滚动或可交互工具栏当作导出要求。代码的折叠、复制按钮和缩进操作在阅读区验收；导出保留完整静态内容。

`network-image.md` 使用原技术方案中的网络图片地址，需要联网。先确认网络图片在正文加载，再测试放大与导出；网络访问失败和本地图片排版分别记录。

## 默认行高与打开最近文件

1. 打开设置，连续点击「阅读」确认分组能展开、收起、再展开，收起不改变右侧阅读配置。确认正文默认行高为 1.6；改为 1.5 后重启，确认自定义值保留。旧版仍为 1.8 的默认设置会升级到 1.6。
2. 打开本目录的 welcome.md、acceptance.md，再通过「打开文件夹」打开本目录；「文件 → 打开最近文件」应有文件夹与文件两个分组，路径清楚可辨。
3. 点击已经打开的 welcome.md 历史项，应切换到原标签，不增加标签数。打开同一文档的符号链接同样不应产生重复标签。
4. 点击「更多…」或按 ⌃⌘R，搜索 welcome；方向键选择、Enter 和鼠标均可打开，Escape 关闭。搜索接受文件名或路径，英文不区分大小写。Windows 快捷键为 Ctrl+Alt+R，当前尚未实机核验。
5. 退出后重新打开应用，确认最近记录顺序保留。打开失效路径应显示失败并保留当前文档；自动展开父目录和重新加载不新增最近文件夹。
6. 在菜单或「更多…」窗口清空记录，关闭应用后重启，确认记录没有恢复；其它阅读设置保持原值。历史最多 100 条，菜单各显示最新十个文件夹与文档。

## 记录方式

发现问题时记录应用版本、亮暗主题、字体与正文宽度、所在节及操作顺序。Word 同时记录所用软件及版本，PDF 记录页码。对排版问题可附整页与局部截图，方便区分源文、阅读区和文档软件之间的差异。

## 已知边界问题

`mermaid-edge-cases.md` 保留综合验收中发现的嵌套 alt／loop 与长循环说明案例。目前条件标签和循环描述仍可能重叠，阅读与导出均需检查；本项尚未修复，不计入已通过项目。综合样例中的普通条件与循环图用于检查日常场景，不能替代这个边界案例。

Word 胶囊通过两侧缩窄的不换行留白字符实现水平内边距，代码文字仍是独立、可编辑的原文。复制代码文字可保留原文；如果连同整个胶囊的留白一起选中，会包含两侧的空白字符。正文阅读区、Markdown 源文与 PDF／HTML 导出不使用这段 Word 留白。

## 行内代码与提示块导出专项

使用 `export-inline.md`，包含截图中的原句、无外侧空格、中文与中英混排胶囊、相邻胶囊、加粗／斜体／删除线、原始 HTML code、表格、无标题 `:::`、全部提示类型及嵌套 JSON。

1. 阅读区：Mermaid 的操作栏与代码语言栏底色一致，亮暗主题都检查。
2. Word：提示块中的 `needAddress=false` 灰底与两侧留白完整，没有边框。保留原生可编辑代码文字。
3. PDF：`**version**` 等内联强调正常显示；`接口文档` 及中英混排胶囊只有一层边框；无外侧空格时也不覆盖相邻正文。长胶囊换行后文字完整。
4. HTML：无标题块图标对齐正文第一行；有标题提示块图标与标题居中。缩窄窗口并查看多段正文、列表和嵌套代码。

本轮自动检查包括真实四格式导出、PDF／DOCX 的逐页渲染、HTML 的离线 CSS 排版及几何检查。DOCX 自动渲染使用 bundled LibreOffice，HTML 离线检查使用 WeasyPrint；不等同于 Microsoft Word、浏览器或 Windows 的实机验证。

## Markdown 基础样式专项

打开 `inline-emphasis.md`：检查正文、各级标题、引用、列表、普通及多行表格、提示块标题和正文的加粗、斜体、删除线及混合强调。行内 code 内的有效强调也应生效，仍能原生选择、复制和搜索；普通标识符及代码块／Mermaid 源码保持字面值。分别导出 PDF、Word 和 HTML 检查相同内容。Markdown 导出须与原文一致。

## 0.8.4 图文对齐与分页专项

先打开 `callout-alignment.md`，检查前两块的中文／英文、全部提示类型、混排标题、列表、JSON 和两个表格。图标应与首行可见文字对齐，换行不改变对齐目标；应用中切换主题与字体，导出检查同样内容。Word 图标后留白为8pt，短块内代码顶部与底部边框、JSON 图标及表头底色应完整。

再打开 `callout-pagination.md`，导出 Word 与 PDF。默认配置下两者均为4页：短提示块完整移到下一页，长提示块随正文分页，「高于一页的提示块」标题后直接开始内容，不应出现只有标题的空白页；最后保留「跨页末尾仍可见」。更换字体或文档软件后页数可以变化，内容完整与边框才是验收依据。

Word 的默认中文字体选择 Office 可枚举的系统字体，明确自选字体保持；接收方未安装同款字体时仍可能回退。DOCX 内容保留原生可编辑文字，没有为对齐将正文转换成图片。
