# Word 连续代码卡片与表格底色

后续用户验收发现表格行内代码上下边框裁切，并指出 3pt 外框过粗。0.8.7 已替换该行框与外框方案；本文保留当时的验证记录，不能作为这些后续问题已解决的依据。详见 [0.8.7 修复记录](review-0.8.7.md)。

当前实现移除 Word 代码表格的 1pt 单元格间距，修正语言栏与代码正文之间的白色接缝。外框使用 3pt、DEDEDE 浅灰原生单元格边框，表格层边框关闭；语言栏独占 0.5pt 分隔线。普通、::: 与提示块内代码统一使用 code_block()，不引入另一条渲染路径。

Word 表格此前只给表头写入底色，内容单元格会透出外层 :::、提示块或引用块的背景。现在通用 cell_start() 明确写入浅灰表头和白色内容底色，所有嵌套层级使用同一路径，不针对某一种提示块设置例外。

代码继续保留完整可编辑段落、语法高亮和跨页重复语言栏，语言栏最低 24pt；原有内容内边距、灰色背景、提示块 8pt 图文间距、表格 Markdown 列表解析均保持。未新增依赖、自绘边框、图片化代码、缓存、任务或全文预排。

250 项工作区测试通过，10 项既有环境专项默认 ignored。rustfmt、全目标全特性严格 Clippy 与 warnings-as-errors rustdoc 通过。新表格背景回归在撤销修复时失败，覆盖正文、引用、::: 和有标题提示块中的原生表格，确认背景独立且列表与强调保留。结构回归确认代码卡片没有单元格间距、两行背景各自保持、完整源码和续页语言栏保留。两份生产样例的 HTML、PDF、Markdown 与 0.8.5 逐字节一致。

Microsoft Word 原生核验确认 75%、100%、125% 下普通 Rust、::: 内 JSON、提示块内 YAML 的语言栏连续性和底边；新表格内容行为白色，表头维持浅灰，基础行内格式和原生列表正常。滚动至第 4 页后，第 90 行下方底边完整，续页语言栏重复。缩放通过原生对话框切换，实际 A4 页面宽度约为 446、594、744 像素，不以状态栏数值单独判断通过。此前用户也已确认无间距方案的语言栏连续、底边存在。
