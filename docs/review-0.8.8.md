# Word 表格与提示块对齐

后续用户在 Microsoft Word 验收中仍发现胶囊白条及上下边缺失，本记录属于 0.8.8 的历史核验范围。当前修订及后续原生验收结果见 [0.8.9 验证记录](review-0.8.9.md)。

0.8.8 修订 Word 导出。用户指出表格内胶囊额外行距影响单元格内容居中，提示块图标偏高。本轮只修改 Word 排版路径，保留应用、HTML、PDF 的现有布局。

## 统一单元格排版

删除 `TableCode` 样式、临时样式范围跟踪和等长 XML 字符串替换。含胶囊与普通文本的所有单元格段落都使用 `TableCell`：1.15 倍自动行距、段前段后零留白。原生 `vAlign=center` 和自动行高保留，不再通过放大段落行框增加胶囊外部间距。

胶囊自身的灰底 F2F2F2、0.5pt 字符边框、1pt 原生边框留白及着色的窄 NBSP 左右内边距保持。代码卡片仍使用同一原生两行表格，0.75pt 外框、0.5pt 分隔线和 24pt 最低语言栏不变。保留末尾空段落标记字号与精确行高一致的修复，以及提示块内代码下方的 3pt 外部留白。

## 图标跟随原生文字基线

删除 DrawingML 段落锚点分支和通过段落顶端推算图标位置的逻辑。提示块和无标题 ::: 共用已有的原生 `wp:inline` 图片路径。根据首行可见字形中心计算图标 run 的 `w:position`，按 Word 半磅单位取整；文字 run 不设偏移，最终行框、换行和分页由 Word 处理。图标保留 12pt 大小和固定 19pt 横向 gutter，续行使用原生悬挂缩进。

测量继续复用现有字体目录和字形指标，不增加全文预排、第二套字体扫描、常驻任务或依赖。字体、加粗和斜体参与已有按需测量，胶囊 padding 不进入字形中心计算。

原生 Word 三种对照为 A 可见字形测量与行内基线、B 原生行内居中、C 原生行内顶端对齐。用户确认 A 最齐，最终生产实现采用 A；B、C 仅保存在 QA 对照文件中，没有进入生产代码。

## 回归与实际显示

全工作区全特性串行测试 251 项通过，10 项既有环境专项默认 ignored。rustfmt、严格全目标全特性 Clippy 和 warnings-as-errors rustdoc 通过。测试覆盖统一单元格样式、原生垂直居中、胶囊基础 Markdown 格式、列表、提示图标只移动图片 run、原生 XML 顺序、代码完整性、细边框、连续语言栏及必要空段落。

三份生产样例的 Word 共 8 页经 bundled LibreOffice 渲染并逐页检查，表格背景、列表、胶囊、嵌套 JSON/YAML、续页语言栏与第 90 行细底边保留。LibreOffice 检查不代替 Microsoft Word 原生显示。

Microsoft Word 的 100% 表格画面已观察到行高恢复、内容居中和胶囊边框可见；原生 A/B/C 对照已打开并截图，用户选择 A。未重新完成所有样例和 75%／100%／125% 的完整原生缩放矩阵，不将自动渲染结果当作该矩阵全部通过的证据。
