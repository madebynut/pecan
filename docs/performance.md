## 0.7.1 多语言高亮与格式化导出

启用 gpui-kit 的现成 Tree-sitter 语言集合，37 个 grammar 包含 Markdown 行内语法；补齐 SQL、TSX／JSX、C／C++／C#、Swift、GraphQL、Proto、CMake 与模板注入查询。高亮与格式化支持范围独立，Rust、Python 等无需格式化器也能着色。正文和 HTML、Word、PDF 使用同一 fence 语言识别与主题；大小写、数据库别名和 fence 附加参数统一规范化。Vue／XML、SCSS／Sass／Less 使用宿主语法，专用扩展不保证全部着色；未知语言仍是纯文本。

语法资源随二进制静态链接，只有遇到代码块时创建其高亮器并解析代码，未启动外部进程或运行时网络请求。沿用原生 Editor 的后台解析、可见行塑形及全文展开、水平滚动、边框修复。导出单块高亮限制 256 KiB、单行 16 KiB，超过限制保留完整代码而省略着色。

PDF、Word、HTML 按全局 Tab 配置使用格式化代码，覆盖顶层、引用与 :::；单块工具栏临时 Tab 选择仅影响该阅读块。导出以不可变 Arc 快照共享同配置的已准备结果；关闭标签不会使导出结果失效。未准备块在后台格式化，相同源码复用结果。与加载／单块操作共用最多两项格式化任务；额外导出缓存上限 8 MiB、4096 项，累计格式化耗时预算 2 秒，达到限制后保留原文。此预算不含等待任务、全部图文排版时间，也不是整个进程内存上限。各格式化器继续限制输入大小、输出大小与复杂度；语法无效或源码映射不可靠时安全保留原代码。源 Markdown 与 Markdown 导出不改写。

## 热路径

滚动只访问可见行与有限预取范围。普通行以顶层标题和约 8 KiB 的字节预算划分完整 Markdown 块；不拆开普通表格与列表；围栏代码按 16 KiB／128 行分段。内容已经缓存时复用 GPUI 实体，未缓存时只建立当前行的组件。文件索引、全文搜索、Mermaid 布局和栅格化均移至后台。

GPUI Kit 的完整 TextView 默认首次测量所有内容，本项目在外层使用 `ListState::with_uniform_item_height` 的可见项测量模式，每行 TextView 不启用自己的文档级滚动。初始滚动条高度是估算值，随着行被测量逐步收敛；大纲使用语义行索引直接定位。异步解析中的行保留 600px 占位，并向列表报告测量尚未就绪；解析完成后只通知一次占位状态变化，避免空行反复填满视口、互相淘汰并重新解析。

代码高亮由组件按代码块缓存。源码与文档索引通过不可变共享数据传递。搜索结果转换为渲染文字范围后高亮；查询防抖 180 ms，最多保留 4096 个结果。

## 资源预算

| 资源 | 预算 |
| --- | --- |
| 单篇源文档 | 32 MiB |
| 同时打开的源文档 | 64 MiB / 8 个标签 |
| 当前文档 UI 行缓存 | 32 行 |
| 当前文档图表预览缓存 | 8 张 |
| Mermaid 同时任务数 | 2 |
| 单个 Mermaid 源码 | 128 KiB |
| 图表节点 / 边 | 512 / 2048 |
| 单张 SVG 输出 | 4 MiB |
| 图表缓存 | 64 项 / 32 MiB 估算费用 |
| 大图栅格化 | 单边 ≤4096 像素 / ≤800 万像素 |

图表缓存费用以 SVG 长度的四倍估算，包括解析几何的余量；它不是进程内存的硬上限。字体数据库、GPUI、原生平台、临时后台数据以及 GPU 纹理另占内存。

Markdown 的语义边界可能超过 8 KiB。单个语义块超过 64 KiB 时，改为按 16 KiB 的 UTF-8 安全页查看完整源码；围栏代码走独立的连续虚拟行路径，不使用分页或内部滚动，复制图标仍复制完整原始代码。避免在主线程建立巨大表格、代码或单行文本的完整富文本布局。单篇超过 32 MiB 时返回可读错误。

上述 64 KiB 预算也检查没有完整块事件的原始 HTML、引用定义尾部，以及追加给阅读块的引用定义；这些输入不能绕过限制。大纲显示文字最多 512 字节，超长标题仅缩短显示标签，源文档保持完整。

## 0.2 新增功能的预算与实测

LaTeX 与化学式在专门的后台准备阶段处理，最多两项任务并行；GPUI Markdown 插件只查找已准备的不可变图像，不在解析或绘制热路径运行公式引擎。普通不含美元符号的文本继续使用原来的直接 Markdown 路径。

### 定位与修复

GPUI 默认资产系统的已加载结果会一直驻留到 remove_asset；虚拟行 Entity 被淘汰不等于这些结果被移除。旧版正文图片、公式，以及 Mermaid 预览缩放或主题切换生成的历史栅格都可能累计解码像素与 GPU atlas 项。

正文资源图片采用元素状态持有的局部图片缓存；退出可见行时清理解码结果和 atlas。公式及内嵌编码图像采用可见元素拥有的栅格状态。Mermaid 卡片在行释放时清理图像，预览在新栅格替换、主题切换与窗口释放时清理旧图像。已解码图像直接用于重绘；共享同一编码图像的其他视图仍保留自己的像素引用，不因一次缓存移除立即重复解码。普通图片备用预览也在窗口释放时清理源与纹理。图片全尺寸 Quick Look 和矢量高清放大保留。

系统字体数据库采用进程级 OnceLock 共享，多个渲染队列不重复发现字体。按需字体实验因中文 regular/medium 选择差异被淘汰，最终保留完整字体覆盖；没有用改变字形或缩小预览分辨率换取指标。

## 0.6.2 网络、侧栏与渲染修复


暗色 LaTeX 的根因是 SVG 的 `currentColor` 依赖 CSS 根选择器，而栅格库未按预期解析该选择器。本版将主题前景色解析到实际 SVG 颜色值；测试检查亮暗两种主题下的字形、分数线和化学键像素，用户指定的 LaTeX 颜色保留。

网络图片此前使用 GPUI 默认空 HTTP 客户端。本版接入与 GPUI 兼容的 rustls HTTP 客户端，1 个 Tokio worker、最多 2 个同时请求；连接超时 10 秒，总超时 30 秒，默认重定向上限 10 次，请求与响应各限制 16 MiB。尊重 GPUI 的更短超时与重定向策略；图片被淘汰时取消未完成网络任务。用户技术方案中的 PNG 经真实客户端与 GPUI 解码器成功加载，原始尺寸 3780×2380。

最终交互核验还发现点击网络图时调用了仅适用于绘制阶段的 `Window::use_asset`，缺少当前绘制视图会导致 panic。现在点击回调复用正文可见元素已经持有的完整 RenderImage，再交给 Quick Look 导出；不在回调里访问绘制接口，不再次下载或解码，也不缩小原图。Quick Look 像素上限调整为 16×1024²，输出文件仍限制 32 MiB；逐行转换 BGRA 并流式编码 PNG，这张 3780×2380 原图的颜色转换缓冲从约 34.3 MiB 全图副本改为 15,120 字节的一行，编码器另有小缓冲。新增大图首尾像素与完整行数的回归验证。尚未加载的图片使用现有异步备用预览。纯回归测试在不存在 Window 的情况下准备 3780×2380 像素快照，确认保留相同 Arc 与完整尺寸。

富表格只处理实际 HTML AST 节点，行内 code 中的字面 `<br>` 保留。源码采用 SharedString，列宽权重在解析时计算；普通表格保留原生快速路径。有效的单行 GFM 表格支持 `<br>` 分隔的列表、强调、链接与行内 code，不改变 Markdown 的跨行表格语法。

侧栏默认 230px、展开最小 160px；最大为 400px、窗口宽度 35% 及保留正文 360px 后可用宽度之间的较小值。拖动超过上限立即夹限，反向拖动没有累计超距死区；接近外缘收起，边缘保留拖回展开的交互区域。纯状态与实际 GPUI 鼠标事件测试均覆盖两侧，并已实机验证。
