# Word 表格列表与代码边框修复

GFM 表格的单元格原本只有行内解析事件，Word 导出因而将列表标记作为文字输出。现在仅对包含真实 HTML 换行／列表标签或列表前缀的候选单元格恢复块级 Markdown，再进入既有 Word 序列化流程。普通单元格保留借用事件，富单元格每次只缓冲一格。列表、强调、删除线、链接、行内代码等共用正文路径；引用式链接和图片复用全文的定义。代码中的标签、转义标签和管道保留字面含义。标准表格仍要求一行单元格位于同一物理行，可使用 `<br>` 表示内容换行。

Word 的合并边框在嵌套代码表格中出现缩放相关的底边丢失。代码卡片改用原生单元格边框，原生单元格间距为 1pt，外框为 1.5pt 灰线；表格层边框显式关闭，只有语言行绘制内部的 0.5pt 分隔线，避免重复边框。代码继续保留可编辑段落、完整内容、语法高亮和跨页重复语言栏；语言栏最低高度仍为 24pt。普通表格、行内代码、应用代码卡片及其他格式的排版路径保持。

249 项工作区测试通过，10 项既有环境专项默认 ignored。rustfmt、全目标全特性严格 Clippy 与 warnings-as-errors rustdoc 通过。表格回归覆盖单项／多项列表、有序起始编号、嵌套 HTML 列表、任务列表、基础行内格式、代码内字面标签、转义管道及全文引用。列表和引用式链接回归均确认修复前失败。

Microsoft Word 原生画面确认 75% 和 100% 下普通代码、`:::` 内 JSON、提示块内 YAML 的底边框完整，表格列表、表头与基础格式正常。后续窗口捕获失败，125% 与跨页末尾没有取得可靠的原生画面，不将状态栏数值或旧截图视为通过。bundled LibreOffice 完成两份 Word 样例共 6 页的逐页检查，90 行代码完整、续页语言栏与最终底边框正常；这一结果不替代 Microsoft Word 实机显示。

原提示块样例的 HTML、PDF、Markdown 与 0.8.4 最终产物逐字节一致。未新增依赖、常驻任务或全文预排，不进行新的 RSS／FPS 声明，也未完成 Windows 实机验证。
