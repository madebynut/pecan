# Word 胶囊间距与原生代码边框

0.8.7 初版没有通过用户验收：语言栏连续，但表格胶囊上下边框和长代码底边仍有缺失。本记录说明后续修订，初版的 `release/` 输出不代表本次交付。

后续用户验收指出：`TableCode` 的额外段落留白与放大行距影响单元格内容居中，提示块图标也仍有偏差。0.8.8 已移除该样式并改为原生行内图标对齐；本页保留历史方案，当前实现与核验范围见 [0.8.8 记录](review-0.8.8.md)。

## 原生空段落的行框

代码表格后的必要空段落原先只有 1pt 精确行高，却继承 11pt 正文字号的段落标记。Word 的绘制可能覆盖前一张表格的细底边。现在所有代码和提示框共用 `table_gap()`，给段落标记指定与精确行高匹配的字号，不再让正文大小的段落标记进入 1pt 空行。

普通代码后的空行仍为 1pt；按照用户的新要求，::: 和有标题提示块内的代码后增加到 3pt。该段落位于代码表格外，提供真实的外部下方留白；代码内部 padding 不变。保留原有 4pt paragraph-after，它在容器末尾可能由 Word 折叠，实际外部留白由 3pt 行框保证。

代码语言栏和完整正文继续属于同一原生两行表格，外框为 0.75pt、内部分隔线为 0.5pt。保留 24pt 最低语言栏、续页重复语言栏、不透明背景、完整可编辑代码和语法高亮。逐代码行拆分表格的实验未能解决嵌套底边问题，未纳入最终实现。

## 胶囊与单元格

胶囊保留 0.5pt 字符边框和 F2F2F2 灰底，原生字符边框留白由 0 增至 1pt。Word 的字符边框距离作用于四边，不能单独指定上下，也不会将字符底纹延伸到全部边框距离；原有左右着色的窄 NBSP 边缘保留，没有改变字符字号或将可编辑代码变为图片。

普通表格段落保留 `TableCell` 的 1.15 倍自动行距；仅含胶囊的段落采用继承它的 `TableCode`，使用 1.4 倍自动行距和上下各 1pt 的段落留白。单元格继续使用原生垂直居中，行高由 Word 自动增高，没有精确行高裁切。样式选择在输出段落时完成，不引入全文测量或额外解析。

## 检查与原生核验

按现有 CI 命令运行全特性串行回归，251 项通过、10 项既有环境专项 ignored；rustfmt、全目标全特性严格 Clippy、warnings-as-errors rustdoc 通过。默认并行复测仍有三项 GPUI 应用测试失败，其中调度器报告共享格式化信号量跨测试线程唤醒；该项目既有 CI 已要求串行测试。首次失败的两项独立复测通过，三项均在全特性串行回归中通过，未修改应用或测试代码。回归检查覆盖表格基础格式与列表、胶囊语义样式、原生代码共享细外框、空段落标记字号、外部下方留白、单元格垂直居中和代码完整性。

三份生产样例的 Word 输出共 8 页，经 bundled LibreOffice 渲染并逐页检查：胶囊边框、表格背景、列表、语言栏、嵌套 JSON/YAML 和第 90 行底边完整。三份样例的 HTML、PDF、Markdown 与初版 0.8.7 对应文件逐字节一致，改动仅涉及 Word 导出。
